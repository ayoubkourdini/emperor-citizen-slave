# Git workflow

1. Garder `main` pour la version stable et `develop` pour le travail en cours.
2. Créer une branche par fonctionnalité, par exemple :
   - `feature/players-crud`
   - `feature/game-duel`
   - `feature/history-filters`
   - `feature/local-storage`
   - `feature/responsive-ui`
3. Faire de petits commits avec des messages clairs.
4. Ouvrir une Pull Request vers `develop` avec une description et une checklist de test.
5. Demander au camarade de relire la Pull Request.
6. Corriger les remarques avant la fusion.
7. Relier chaque Pull Request à la carte correspondante dans GitHub Projects.
8. Tester le site après chaque fusion.

## Avant une Pull Request
- [ ] La fonctionnalité est testée.
- [ ] Aucune erreur dans la console.
- [ ] La mise en page fonctionne sur mobile et ordinateur.
- [ ] Le README / la carte de projet est mis à jour si nécessaire.
